description: 汇总工作区全部改动，生成规范中文提交信息并提交
---

请为当前工作区完成一次提交，全程使用中文，严格按以下步骤执行：

1. 并行收集事实：`git status --short`、`git diff --stat`、`git diff`（未暂存）、`git diff --cached`（已暂存）、`git log -20 --format=%s`，并阅读仓库根的 `AGENTS.md`（若存在）。
2. 判断提交规范：优先沿用本仓库既有提交历史的语言、`type(scope)` 前缀与正文结构；历史无法判断时，使用 Conventional Commits 形式 `feat|fix|refactor|perf|docs|test|chore|build|ci(scope): 摘要`，scope 取实际受影响模块的小写英文名。
3. 若工作区没有任何改动（含未跟踪文件），直接说明并结束，禁止创建空提交。
4. 暂存：`git add -A`（包含未跟踪文件，不含被忽略内容）。提交前自查完整 diff：一旦发现密钥/token/证书、数 MB 以上二进制、依赖目录或构建产物，立即停下并报告，不要提交，等我处理。
5. 提交前先写出完整提交信息草稿，必须满足：
   - 首行：`type(scope): 中文摘要`，不超过 72 字符，说清“做了什么”，完成时态，结尾不加句号；
   - 空一行后写正文，按主题分节（例如「数据库与迁移」「后端」「前端」「契约与文档」「验证」），每节用 `-` 列出能从 diff 逐条核对的具体改动：新增或修改的接口路径、迁移编号与表结构变化、组件与函数名、字段与枚举、契约或 schema 版本号、行为与时序变化；
   - 只陈述 diff 与代码能证实的事实，不臆测动机；禁止「修改了一些文件」「优化代码」「修复若干问题」这类空话；
   - 涉及数据流向、接口签名、配置格式变化时必须写明；确实执行过验证才写「验证」节并列出真实命令与结果，没跑就不写。
6. 执行 `git commit` 提交（多加的 `-m` 段落或 `-F` 临时文件承载正文，保持上述换行结构）。不加 `--no-verify`，不 `--amend`，不改写历史。
7. 提交后用 `git log -1 --stat` 复核，报告提交短哈希、首行摘要与改动文件数。
8. 不执行 `git push`；除本次提交动作外不修改任何文件、不改动文档（同步文档只有在本次 diff 已包含相应改动时才算）。

附加要求（若我填写，以它为最高优先级）：$ARGUMENTS
